# Porting roadmap

Size of vanilla 1.21.1 (decompiled, `net.minecraft.*`): **4053 files, ~470,000 lines**. Breakdown (lines):

| Subsystem | Files | Lines |
|---|---:|---:|
| `world/entity` (entities, mobs, AI, player) | 594 | 94,049 |
| `world/level/block` (block behaviour, block entities) | 418 | 58,221 |
| `world/level/levelgen` (world generation) | 418 | 42,113 |
| `world/item` (items, components) | 255 | 24,946 |
| `network` (protocol) | 380 | 23,899 |
| `server/commands` + `commands` (Brigadier) | 208 | 26,227 |
| `world/level/storage` (world saving) | 145 | 10,259 |
| `server/level` | 38 | 9,889 |
| `advancements` | 111 | 8,078 |
| `world/level/chunk` | 53 | 7,317 |
| `world/inventory` | 60 | 6,282 |
| `nbt` | 40 | 5,829 |
| `world/level/lighting` | 15 | 2,304 |

Method for every stage: **(1)** read the decompiled code with official names, **(2)** port the logic,
**(3)** prove parity with a differential test against the real Mojang classes (like `tools/verify/Verify.java`: a Java
harness runs the original code on the same inputs and compares results) and against the real vanilla server
(`tools/vanilla_compare.sh`), **(4)** only then move on.
Where the logic is *data driven* (density functions, noise settings, loot tables, enchantments, recipes, advancements)
we port a data interpreter, not every class separately.

After every stage a pull request is opened and merged; each PR describes what was verified and how.

## Stages

**M1 ✅ Network foundation** (merged): handshake/status/login (offline+online)/configuration/play (join, chunks, player
movement, chat, block changes), verification with the real codecs and a differential test against the vanilla server.

**M2 ✅ World on disk** (merged). Anvil reader/writer (`.mca`, zlib/gzip/LZ4/none), chunk NBT ↔ sections (block name +
properties ↔ state ID from `blocks.json`), stored light and heightmaps, `level.dat`, `playerdata/*.dat`,
`level-name`/`level-seed`. Result: loading an existing Java server world 1:1. Verification (`tools/world_compare.sh`): chunk packets for a world
generated by the vanilla server are compared byte for byte with the packets the vanilla server sends (109/109 chunks
identical); a world saved by the Rust server is loaded by the vanilla server and only the edited block differs.
Still open from this stage: executing the stored scheduled ticks (M7), light that depends on neighbouring chunks that are
not stored (M4/M5), saving light/heightmaps of edited chunks (M4), entities/POI/structure data are preserved but not used (M6, M10, M11).

**M3 ✅ Block and item property tables** (`tools/dump_props.sh`). `blocks.json` does not contain hardness, collision, light opacity, emission or
fluids. A small Java program runs the real `Block`/`BlockState`/`Item` classes after `Bootstrap` and dumps, per state: hardness, blast
resistance, friction, light emission and opacity, 18 flags (`isAir`, fluid, replaceable, solid, ...) and the collision / outline /
occlusion / support / face-occlusion voxel shapes; per item: stack size, durability and the placed block. The Rust server loads the
tables at start (`mc-data::props`) and a test checks known values of the real classes. First consumers: block placement (item →
block, replaceable blocks, collision shapes vs. player hitboxes — differential test with a torch and a pressure plate). Still to come
with their stages: full default component maps (M8), tool speeds and survival mining timings (M7/M8).

**M4 ✅ Light engine** (block and sky light, heightmap types; `tools/light_check.sh`). Still open from this stage: incremental updates and `light_update` packets after block edits, `propagateFromEmptySections` (floating islands), multithreaded lighting. Port of `world/level/lighting` (sky/block light BFS, `DataLayer`), full heightmaps
(`MOTION_BLOCKING`, `OCEAN_FLOOR`, …) instead of the simplified ones. Replaces the simplified sky light.

**M5 — World generation** (the biggest seed-parity risk). Done so far, in `crates/mc-worldgen` and bit-identical to the Mojang
classes: random number generators and noises (`tools/verify_noise.sh`, 878 values); the density function graph, the wired
`NoiseRouter`, `NoiseChunk` with cell interpolation, the aquifer and ore veins, i.e. the terrain shape of every vanilla noise setting
(`tools/verify_terrain.sh`: 5,760 router values, 34 chunks); the biome sources (`Climate` with the R-tree, `OverworldBiomeBuilder`, nether
preset, End, world spawn search; 246,907 values). Still to do: `Beardifier` / terrain adaptation to structures, surface rules (`SurfaceSystem`), carvers, features / placed
features, structures, and wiring the generator into the server (chunks missing from the region files, new worlds, other dimensions).
Verification: the same seed → the same blocks as the real generator in a Java harness, chunk by chunk, stage by stage.

**M6 — Entities and physics.** `Entity`/`LivingEntity`/`Player`, AABB and `VoxelShape` (collisions), movement validation
(`ServerGamePacketListenerImpl.handleMovePlayer`: "moved too quickly/wrongly"), attributes, effects, damage,
death/respawn, metadata and entity tracking, dropped items, XP orbs.

**M7 — Block behaviour.** `getStateForPlacement`, neighbour updates, random ticks, fluids, redstone, doors/chests/furnaces
etc. (block entities + NBT), survival mining with real timings (after M3).

**M8 — Items, inventory, crafting.** Data components (57 types) and their codecs, menus/containers (`world/inventory`),
recipes (`ClientboundUpdateRecipesPacket` + recipe book), loot tables (data interpreter), enchantments (data-driven
effects).

**M9 — Commands and administration.** Brigadier port, the command tree (`commands.json` → `commands` packet), all commands,
`ops.json`/`whitelist.json`/`banned-*.json`, permission levels, server console.

**M10 — Mobs and AI.** Goal selectors, navigation/pathfinding, spawning, trading, breeding, bosses.

**M11 — Dimensions and structures.** Nether/End, portals, template-based structures (`StructureTemplate`, jigsaw).

**M12 — Remaining infrastructure.** Signed chat (`enforce-secure-profile`), advancements, scoreboards, boss bars, maps,
statistics, resource packs, RCON/query, transfers, multithreaded chunk generation/loading (rayon).

## Black-box verification

The best "1:1" test is to run the **real vanilla server** next to the Rust server and compare packet sequences for
identical events. This requires the owner of the environment to accept the Mojang EULA (`eula=true`);
`tools/vanilla_compare.sh` does so only with an explicit `MC_EULA_ACCEPTED=true`. It currently compares 36 aspects of
the join sequence, chat, commands, protocol rejection, chunks and block changes; every new stage extends it.
